## Что проверено сейчас

Проверка выполнена чтением публичных записей, в том числе непосредственно у авторитетного сервера `dns1.registrar-servers.com`. DNS не изменялся, письма не отправлялись.

| Имя | Наблюдение |

| `wextheory.cv` | MX-записей нет; корневой SPF TXT не найден |
| `_dmarc.wextheory.cv` | Есть `v=DMARC1; p=none;` |

| `resend._domainkey.mail.wextheory.cv` | Есть публичный DKIM-ключ |

Сайт в исходном коде отправляет письма от `no-reply@mail.wextheory.cv`. У этого отдельного поддомена есть связанные с Resend/SES записи отправки. Они не создают входящий `support@wextheory.cv`. Доставка регистрационных писем этой проверкой не подтверждена.

Отсутствие MX **не доказывает отсутствие оплаченного тарифа**: услугу могли купить и не настроить. Это выясняется в разделе Private Email личного кабинета Namecheap. [Официальное описание раздела и управления подпиской](https://www.namecheap.com/support/knowledgebase/article.aspx/1167/2177/how-do-i-renew-my-namecheap-private-email-subscription/).

Повторить только чтение DNS можно командой `powershell -File scripts/check_domain_mail.ps1` из корня проекта. Скрипт выводит JSON, ничего не меняет и не проверяет пароль/существование ящика.

Рекомендуемый основной адрес: `support@wextheory.cv`. Адрес `privacy@wextheory.cv` можно сделать псевдонимом того же ящика. Они пока не считаются подключёнными и не добавлены на сайт как работающие контакты.

## Вариант для полноценной поддержки

Один настоящий почтовый ящик с приёмом и отправкой от домена. Если у Namecheap уже есть подходящий почтовый тариф, использовать его. Иначе выбрать почтовую услугу после проверки цены и срока оплаты. Покупка автоматически не выполняется.

Это позволяет отвечать с адреса поддержки, а не раскрывать личный email в ответах. Существующая отправка регистрационных писем через Resend не создаёт входящий ящик поддержки.

## Бесплатный промежуточный вариант

Namecheap поддерживает [Free Email Forwarding](https://www.namecheap.com/support/knowledgebase/article.aspx/308/2214/how-to-set-up-free-email-forwarding/) для доменов с подходящими DNS-настройками. Можно перенаправлять письма с адреса поддержки на существующий ящик.

Для этого нужны подтверждённый DNS-провайдер и адрес назначения. Само перенаправление не создаёт полноценную отправку от адреса поддержки. При ответе из личного ящика без дополнительной настройки получатель может увидеть личный адрес.

## Последовательность настройки

1. Открыть домен в Namecheap и проверить текущие Nameservers и Mail Settings.
2. Сохранить существующие записи сайта и Resend. Не переключать Nameservers ради почты без переноса действующих записей.
3. Выбрать настоящий ящик либо временную пересылку. Использовать конкретные MX/TXT значения выбранного провайдера.
4. Проверить SPF, DKIM и DMARC. Не добавлять вторую конкурирующую SPF-запись для того же имени; учесть существующую отправку.
5. Направить тестовое письмо с внешнего ящика на support, проверить получение и папку спама.
6. Ответить обратно и проверить адрес отправителя и аутентификацию.
7. Проверить регистрацию и восстановление пароля сайта после изменения DNS.
8. Только после успешной проверки заменить/дополнить публичные контакты сайта.

## Если Private Email уже куплен

Сначала проверить домен, статус, срок и доступное место ящика в Private Email → Manage. Если подписка активна и есть свободный ящик, создать `support`; иначе сначала рассмотреть реальное предложение по цене. Покупка и включение автопродления не выполнялись.

Для Namecheap Private Email официально требуются два MX на корне: `mx1.privateemail.com` и `mx2.privateemail.com`, оба с приоритетом 10. SPF для этой услуги — `v=spf1 include:spf.privateemail.com ~all`, если нет других отправителей с тем же SPF-именем. Не копировать DKIM из примера: взять реальное значение из управления подпиской.

Есть важное различие текущих тарифов: для подписок, купленных до 2 июня 2026, DKIM-селектор — `default._domainkey`; для новых — `privateemail._domainkey`. Использовать значение, показанное для конкретной подписки. Существующий DKIM `resend._domainkey.mail` и MX/SPF `send.mail` сохраняются: это другие DNS-имена.

Проверенные инструкции: [MX/DNS на Basic/Premium DNS](https://www.namecheap.com/support/knowledgebase/article.aspx/1338/2176/how-to-set-up-namecheap-private-email-dns-records-for-domains-on-namecheap-basicpremium-nameservers/), [DKIM](https://www.namecheap.com/support/knowledgebase/article.aspx/10383/2176/how-to-set-up-a-dkim-record-for-private-email/), [создание ящика](https://www.namecheap.com/support/knowledgebase/article.aspx/1049/2215/how-to-create-namecheap-private-email-mailbox/).

Подключённого доступа к кабинету Namecheap в этой сессии нет. Для проверки подписки предложен браузерный сервис TinyFish; его установка/подключение пока не подтверждены. Публичный DNS проверен независимо от него.

Нужные сведения: доступ владельца к DNS/почтовой панели, наличие действующего почтового тарифа, а для пересылки — выбранный получающий email. Пароли и коды входа не сохранять в документации проекта.
